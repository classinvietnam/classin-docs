## Receiving & Replying to Help Requests from the Classroom

### I. Receiving help requests

**Who this applies to**
- The Admin Console primary account
- Sub-accounts with "Class Monitoring" access

**When to use this**
When a teacher or student in the classroom needs help, they can use the classroom's help feature to send a request to the Admin Console. Academic staff can log into the Admin Console, find the corresponding session on the Class Monitoring page, and click the issue notice below the session to view what was reported. Staff can then reply to help resolve it.

**Related articles**
- "Adding Sub-accounts in the Admin Console"

**Steps**
1. Log into the Admin Console.
2. Go to Class Monitoring in the left navigation.
3. Find the session.
4. Check for help requests in the bottom-left of the session.

### II. Sending a message to the classroom
Requires the Admin Console primary account.

While monitoring a class, academic staff join as a silent observer and can't interact with anyone in the classroom. If they notice an issue with a specific user, they can send that user a text message from the Admin Console explaining how to resolve it.

**Steps**
1. Click Contact below the session.
2. Choose "Contact Teacher" or "Contact Student."
3. Select the recipient(s), enter your message under "Describe the Issue," then click Send.

## Viewing Class Monitoring Screenshots

### Who this applies to
- The Admin Console primary account
- Sub-accounts with "Class Monitoring" access

### Overview
Academic staff can view classroom monitoring screenshots from the class monitoring detail page. These screenshots are automatically captured by ClassIn from the teacher's viewpoint, saved once per minute.

### Notes
- Class Monitoring shows a maximum of 1,000 screenshots.

### Related articles
- "Entering a Monitored Classroom"
- "Adding Sub-accounts in the Admin Console"

### Steps
1. Log into the Admin Console.
2. Go to Class Monitoring in the left navigation.
3. Find the session.
4. Click on a screenshot thumbnail to view details.

## Account Lookup (View a User's In-Class Device Status)

### Who this applies to
- The Admin Console primary account
- Sub-accounts with "Account Lookup" access

### When to use this
When a teacher or student reports an unstable network or laggy class experience, academic staff can use the Admin Console to check that user's network and device status during class.

### Overview
In Admin Console > Account Lookup, staff can search by a user's phone number or email, plus the class time, to retrieve details of their network and device status during that session. Available data includes: session name, course name, start time, session duration, on-stage headcount, the user's role in the classroom, their network usage and CPU load at each point during class, when they entered and left the classroom, the reason they left, whether they had cloud recording enabled, and whether the recording ran normally. Hovering over a device icon in the device info section shows details of that camera, microphone, or speaker — including whether it was disabled, undetected, which device was selected (if multiple were available), the OS version of the device used, the server they connected to, the device's CPU model, the ClassIn version, and whether they were on wired or wireless network.

### Related articles
- "Adding Sub-accounts in the Admin Console"

### Steps
1. Log into the Admin Console.
2. Go to Account Lookup in the left navigation.
3. Select a date and enter the ClassIn account at the top.
4. View network and device usage during that class below.

## Entering a Monitored Classroom

### Who this applies to
- The Admin Console primary account
- Sub-accounts with "Class Monitoring" access

### When to use this
- When academic staff want to sit in on a teacher's class, they can enter the corresponding classroom from the Class Monitoring page in the Admin Console.
- If a teacher's cloud recording is interrupted due to network or device issues and can't resume, and there's no co-teacher in that session, academic staff can enter that classroom from the Class Monitoring page and start a local recording.

### Overview
To monitor a class, academic staff click "Enter Classroom" on the Class Monitoring page in the Admin Console. The browser will prompt whether to launch the associated app — staff need to click "Allow" or "Open ClassIn" (or similar) to enter the classroom successfully. If the ClassIn app doesn't launch as expected, staff should close any antivirus software and use the "Repair Registry" feature in ClassIn's settings, then try again. Note: entering a classroom to monitor from the Admin Console is free and doesn't incur any charges.

When academic staff enter a classroom to monitor it, they join as an invisible observer — the teacher and students in that classroom can't detect their presence, and staff can't interact with anyone there. However, if the Admin Console account used also has a co-teacher or student role in that classroom, staff will automatically take on that role instead when entering — in that case they can interact with classroom members, and members can see them. Once a staff member enters as anything other than an "invisible observer," normal classroom fees will apply to the Admin Console account.

### Notes
- Class Monitoring shows a maximum of 1,000 classrooms.

### Related articles
- "Viewing Class Monitoring Screenshots"
- "Adding Sub-accounts in the Admin Console"

### Steps
1. Log into the Admin Console.
2. Go to Class Monitoring in the left navigation.
3. Find the session.
4. Click "Enter Classroom."
